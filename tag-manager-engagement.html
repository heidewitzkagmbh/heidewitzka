Tag Manager: 50 Prozent gescrollt – aber hat jemand wirklich etwas verstanden?

Ein genaueres Messkonzept für Angebotsinteresse: relevante Inhalte sichtbar, aktive Zeit und eine konkrete nächste Handlung.

Heidewitzka · 30. September 2026 · ca. 3 Min. Lesezeit

Eine Person scrollt bis zur Seitenmitte. Hat sie das Angebot gelesen? Vielleicht. Vielleicht besteht die erste Hälfte aber nur aus einem großen Bild. Oder die Seite ist so kurz, dass die 50-Prozent-Marke bereits beim Laden sichtbar ist. Scrolltiefe misst eine Position, kein Verständnis.

Google dokumentiert ausdrücklich, dass ein Scroll-Trigger auslösen kann, wenn der festgelegte Abschnitt bereits im sichtbaren Bereich liegt, obwohl niemand tatsächlich gescrollt hat [1]. Ein Ziel wie „30 Sekunden und 50 Prozent“ kann trotzdem nützlich sein. Es braucht nur eine klare Bedeutung und eine Prüfung gegen spätere Geschäftsergebnisse.

Die gleiche Schwelle bedeutet unterschiedliche Inhalte

Die folgende Tabelle beschreibt hypothetische Seiten. Die gemessene Position wird nicht als tatsächlicher Blickkontakt interpretiert.

SituationWas die Schwelle erfasstWas ungeklärt bleibt
Kurze Landingpage50 % möglicherweise schon beim Laden sichtbarHat die Person überhaupt gelesen?
Lange Seite mit großem HeroDie Seitenmitte liegt hinter viel BildflächeWurde das relevante Argument gesehen?
Tab im HintergrundEin Timer kann Zeitablauf erfassenWar die Seite aktiv im Vordergrund?
Schnelles DurchscrollenEin tiefer Abschnitt wird erreichtWie lange war der Inhalt tatsächlich sichtbar?

Vom Seitenmaß zur fachlichen Bedeutung

Ein Messkonzept beginnt mit der Frage, welcher Inhalt für eine Entscheidung wichtig ist. Bei einem Angebot könnten dies Einsatzgebiet, Beispielrechnung und Ablauf sein. Diese Abschnitte erhalten stabile Kennungen. Der Tag Manager kann über Element-Sichtbarkeit messen, ob ein ausgewählter Bereich im Browserfenster erscheint und eine definierte Mindestdauer erreicht [2].

Die Definition wird präzise: etwa mindestens 50 Prozent eines klar begrenzten Inhaltsblocks für kumuliert fünf Sekunden pro Seitenaufruf sichtbar. Google beschreibt die Sichtbarkeitsdauer als kumuliert, nicht zwingend zusammenhängend [2]. Ein sehr großer Abschnitt ist als Messobjekt ungeeignet, wenn die Hälfte auf einem kleinen Bildschirm nie gleichzeitig sichtbar sein kann.

Aktive Zeit benötigt eine eigene Definition

Für eine anspruchsvollere Bewertung wird zusätzlich Zeit erfasst, während das Dokument im Vordergrund sichtbar ist. Das lässt sich über die Page Visibility API und eine entsprechend geprüfte Ereignislogik abbilden [3]. Ein normaler Timer allein garantiert diese Bedingung nicht.

Auch Vordergrundzeit beweist keine Aufmerksamkeit: Jemand kann telefonieren oder den Bildschirm verlassen. Sie reduziert einen Messfehler, liest aber keine Gedanken. Das Ereignis sollte daher beispielsweise „Angebotsengagement“ heißen und nicht „Produkt verstanden“.

Mehrere Bedingungen müssen wirklich zusammenkommen

Ein mögliches Ereignis entsteht erst, wenn derselbe Seitenaufruf sowohl ausreichende aktive Zeit als auch die definierte Abschnittssichtbarkeit erreicht. Zwei separate Trigger am selben Tag bedeuten nicht automatisch eine UND-Verknüpfung. Eine passende Zustandslogik muss die Bedingungen zusammenführen und pro definiertem Aufruf deduplizieren.

Bei dynamischer Navigation wird außerdem festgelegt, wann ein neuer virtueller Seitenaufruf beginnt und die Bedingungen zurückgesetzt werden. Ein Ereignis aus dem vorherigen Angebot darf nicht das Engagement für das nächste Angebot vervollständigen. Erforderliche Einwilligungen und eine saubere Trennung von technischen und marketingbezogenen Ereignissen gehören in das vorhandene Messkonzept.

Die Validierung kommt aus echten Ergebnissen

In einer eigenen Modellrechnung gewinnen 8 von 100 Leads mit dem Signal einen Auftrag, ohne Signal 4 von 100. Das wäre ein interessanter Zusammenhang. Er beweist nicht, dass das Ereignis den Abschluss verursacht; engagierte Nutzer könnten bereits vor dem Besuch kaufnäher gewesen sein.

Bevor das Signal als Kampagnenziel eingesetzt wird, werden Stabilität, Häufigkeit und Zusammenhang mit qualifizierten Anfragen geprüft. Technische Kontrollen umfassen kurze Seiten, kleine Bildschirme, Hintergrundtabs, Reloads und dynamische Navigation. Ein präziseres Zwischenziel hilft nur, wenn seine Bedeutung wiederholbar bleibt und es tatsächlich näher an einem Geschäftsergebnis liegt.

Quellen und Einordnung

[1] Google Tag Manager: Scrolltiefe-Trigger. Grenzen von positionsbasierten Ereignissen.

[2] Google Tag Manager: Trigger für die Elementsichtbarkeit. Sichtbarkeitsanteil, kumulierte Mindestdauer und Auslösung.

[3] MDN: Page Visibility API. Dokumentation der Browser-API; die kombinierte Messdefinition ist ein eigener Umsetzungsvorschlag.
